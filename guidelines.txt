1. Purpose of the Mini Project
The mini project should demonstrate more than basic CRUD operations. Students should design a business problem as a set of independently deployable Spring Boot microservices and demonstrate synchronous REST communication together with at least one asynchronous event-driven workflow.
Identify clear business capabilities and microservice boundaries.
Use Controller-Service-Repository architecture inside each service.
Apply REST API design, DTOs, validation, exception handling and database persistence.
Use RabbitMQ or Kafka for asynchronous communication.
Demonstrate resilience concepts such as retry, Dead Letter Queue (DLQ) and idempotency.
Use Saga, CQRS or Event Sourcing where the selected problem naturally requires it.
Test the implementation and maintain the source code in GitHub.


11. Courier and Parcel Tracking System
Develop a parcel system that records every shipment movement as an event and reconstructs the current delivery status.

Shipment Service

21. Mandatory Mini-Project Requirements
Minimum 3-5 independent Spring Boot microservices.
At least one database per major service; avoid direct cross-service table access.
REST APIs using appropriate GET, POST, PUT/PATCH and DELETE operations.
Controller-Service-Repository architecture.
At least one clearly identified DDD bounded context.
DTOs, Bean Validation and global exception handling.
RabbitMQ or Kafka for at least one asynchronous workflow.
Demonstration of Publish-Subscribe or Work Queue messaging pattern.
Retry mechanism and Dead Letter Queue (DLQ).
Idempotent message processing.
One Saga workflow when the project contains a distributed business transaction.
JUnit/Mockito tests and REST API testing.
Dockerize the services; Docker Compose is recommended.
Maintain source code and documentation in a GitHub repository.
Provide Postman collection/screenshots or equivalent API testing evidence.
